# NetraX sensor and telemetry contract — v0 draft

**Status:** Design contract. No live sensor or ingest endpoint is implemented by this document.

This contract defines the minimum information that must cross the sensor/control-plane boundary. It is intentionally small for the first release and must be versioned before production deployment.

## Required envelope

A telemetry message must carry:

- `schema_name`: stable contract identifier, e.g. `netrax.flow`.
- `schema_version`: explicit integer/semver; unsupported versions are rejected or quarantined.
- `event_id`: globally unique event identifier generated by the sensor.
- `event_time`: UTC timestamp for observed event time.
- `ingest_time`: assigned by the receiving service, never trusted from the sensor.
- `organization_id`, `site_id`, `sensor_id`: authorized identity scope, derived from authenticated sensor registration rather than accepted blindly from a payload.
- `sensor_version`, `config_version`: reproducibility and rollout traceability.
- `capture_id`: unique capture session identifier.
- `direction_validation`: explicit visibility classification.
- `capture_health`: counters and clock/packet quality indicators.
- `flow`: normalized observation with only fields that were actually measured or derived from the observed packets.
- `feature_schema_id`: identifies the exact feature contract used downstream.

## Direction state

Allowed states:

- `verified_unidirectional`: the capture source is a configured and trusted monitoring point whose topology/configuration establishes which direction is mirrored; evidence and source identity are attached.
- `bidirectional`: both directions are known to be present in the observation.
- `unknown`: no trustworthy direction provenance exists.
- `unverified`: file upload or source that cannot independently establish direction.

A sensor may not set `verified_unidirectional` solely because an operator typed a claim into a form. The control plane must associate the sensor/interface with an approved monitoring-point record and configuration. Unknown/unverified inputs can still be analyzed by detectors whose contract supports them, but must never be represented as one-way validated.

## Capture health

Minimum fields:

- `packets_seen`
- `packets_dropped` (nullable only when platform cannot measure it; reason required)
- `capture_started_at`
- `capture_stopped_at` (nullable while active)
- `clock_source`
- `clock_offset_ms` (nullable with reason)
- `snap_length_bytes`
- `capture_filter_id`
- `interface_id`
- `direction_source_id`
- `buffer_capacity_bytes`
- `buffer_high_watermark_bytes`

## Flow field semantics

- `src` and `dst` identify the packet direction as actually observed at the sensor; do not relabel them as endpoint initiator/responder unless independently established.
- Packet/byte counters must be measured from observed packets only.
- Forward/reverse counters must not be synthesized from missing traffic.
- Duration is the observed time span for the specifically defined observation key. It is not a complete bidirectional connection lifetime unless both directions were observed and the schema says so.
- Missing, truncated, sampled or unsupported features are represented explicitly; they are never silently filled with plausible-looking zeroes.
- Every derived feature set references the versioned extraction implementation.

## Idempotency and replay

- `event_id` must be unique within a sensor identity.
- The receiver deduplicates by authenticated sensor identity + event_id.
- Retries preserve the original event_id and payload digest.
- The receiver records accepted, duplicate, rejected, and quarantined counts.
- A sensor must bound local spool size and report when it drops or expires data.
- Event-time ordering is not guaranteed; processors must tolerate late arrivals.

## Security boundary

- Sensor transport uses mutually authenticated TLS.
- Enrollment binds a certificate public key to a sensor record.
- Credentials are never embedded in the telemetry JSON.
- The receiver derives organization/site/sensor scope from the authenticated certificate and registry, then checks payload identity claims match.
- Certificate revocation takes effect at the ingest boundary.
- Payload size, rate, schema, and queue depth are bounded.
- Evidence retrieval requires separate authorization and is audited.
